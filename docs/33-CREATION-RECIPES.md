# Creation Recipes — M10.1 Closeout

**Cycle**: `m10-1-creation-recipes` | **Status**: done

## What was built

M10.1 delivers a creation-recipe system with two user interfaces — a browser wizard at `/create`
and a CLI with `narrative init` / `narrative plan` — sharing a single declarative recipe source.

## Recipe contents contract

A recipe lives at `recipes/<id>/` with this structure:

```text
recipes/<id>/
├── recipe.yaml           # creation-recipe/v1; metadata + parameters + project
├── parameters.schema.json # JSON Schema 2020-12 for user-supplied parameters
├── ui.schema.json        # optional RJSF uiSchema for wizard presentation
├── skeleton/             # templated files ({{var}}, {{#each}}, {{#if}}, {{!}})
├── recipe.lock.json     # SHA-256 lock (auto-generated by validate.py --publish)
└── README.md
```

## Mustache-subset grammar (Decision 3)

Skeleton files use a restricted grammar. **Parsed, not eval'd.** Forbidden patterns are
rejected at parse time with `TemplateError`:

| Pattern | Error code |
|---|---|
| `{{> partial}}` | `forbidden-partial` |
| `{{{ raw }}}` | `forbidden-raw` |
| `{{ a.b.c }}` | `forbidden-dotted-path` |
| `{{ {{nested}} }}` | `forbidden-nested` |
| `{{ upper(name) }}` | `forbidden-function-call` |

Implemented in Python (`tools/narrative_recipes/template_engine.py`) and TypeScript
(`control-plane/src/recipes/templateEngine.ts`). Both satisfy the same 5-fixture corpus
and produce byte-equal canonical JSON output.

## CLI surface (Decision 4)

```bash
# Initialize a project from a recipe
narrative init --recipe middle-grade-illustrated \
  --param title="My Novel" \
  --param projectId="my-novel" \
  --param audience="profile-middle-grade-10-11" \
  --out /path/to/output

# Dry-run: emit the plan without writing files
narrative plan --recipe middle-grade-illustrated \
  --param title="My Novel" \
  --param projectId="my-novel" \
  --param audience="profile-middle-grade-10-11" \
  --json

# From a downloaded plan file
narrative init --plan create-plan.json --out /path/to/output
```

Exit codes: `0` success, `1` validation error, `2` conflict (without `--force`), `3` missing recipe, `4` internal error.

## Round-trip equivalence oracle (Decision 5)

The recipe system is implemented independently in Python and TypeScript. Canonical JSON equality
(`canonicalJson(stripRecipeOwned(manifest_python)) === canonicalJson(stripRecipeOwned(manifest_ts))`)
is the equivalence oracle, ensuring both paths produce identical output for the same recipe
and parameters.

`stripRecipeOwned` removes `createdAt` timestamps. The canonical form preserves:
`audience`, `format`, `publishing`, `initialGoals`, `project.profiles/packs/skills/publishingTargets`.

## Bundled recipe: `middle-grade-illustrated` (Decision 6)

- **Profile**: middle-grade 10–11, illustrated novel
- **Parameters**: `title`, `projectId`, `audience`, `imagePolicy`, `genre`, `outputLanguage`
- **Skeleton**: 1 narrative.yaml + 1 profile + 2 characters + 3 chapters + 4 pack stubs + goals.yaml = 12 files
- **Image policy default**: `local_preferred`
- **Publishing target default**: `print-pdf`

## Browser wizard (`/create`)

The wizard is registered as a `RecipeWidgetExtension` (kind: `'wizard'`) against the Control Plane Extension Registry. It renders the `CreateWizard` component at the `/create` route. The wizard:

1. Loads the recipe bundle via `useRecipeLoader` (import.meta.glob, async, Map-cached)
2. Renders a form from `recipe.parameters` + `recipe.uiHints` schema
3. Emits a `create-plan.json` via `RecipePlanEmitter` (canonical JSON, SHA-256 fingerprints)
4. Writes to disk via one of two sinks:
   - **FileSystemAccessSink** — uses `window.showDirectoryPicker()` (Chromium only); writes skeleton files + `.narrative/create-plan.json`
   - **DownloadPlanSink** — `URL.createObjectURL` fallback for Firefox/Safari; downloads `create-plan.json` which can then be fed to `narrative init --plan`

The wizard NEVER calls `useProjectionStore` — it cannot mutate Control Plane state (m10 no-write invariant).
